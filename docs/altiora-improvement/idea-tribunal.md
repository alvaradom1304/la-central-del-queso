# Tribunal de ideas de Altiora

Activar cuando el usuario pida un tribunal/debate o cuando una decisión importante tenga alternativas y objeciones materiales. No hacerlo para cada corrección pequeña.

Usar high-value-deliberation para contrastar la decisión y quality-council cuando exista un resultado que revisar. Estas skills ya están instaladas.

1. Definir pregunta, objetivo, restricciones y evidencia común. Separar hechos, supuestos y datos ausentes.
2. Cuando el entorno permita delegación real y esté autorizada, encargar en paralelo un análisis al defensor y otro al crítico. El defensor busca condiciones de éxito; el crítico, supuestos falsables y modos de fallo. Ambos pueden reconocer evidencia contraria y cambiar de postura. Máximo dos analistas inicialmente, contexto mínimo y ninguna escritura simultánea en el mismo archivo.
3. Reunir ambos informes y pedir una réplica breve solo si hay una discrepancia material. Las réplicas dependen de los informes iniciales; no simular que se hicieron antes.
4. El juez actúa después, con acceso a ambas posturas y sus fuentes. Puede ser el coordinador o un revisor separado cuando aporte independencia. Decide avanzar, modificar, descartar o reunir evidencia, explicando condiciones y una prueba pequeña. No decidir por elocuencia, mayoría ni puntuaciones inventadas. No asegurar éxito comercial por consenso entre modelos.
5. Sin soporte de subagentes, hacer contraste secuencial y declararlo; no llamarlo revisión independiente ni paralela. No abrir APIs de pago o cambiar modelos por defecto para simular agentes.
6. Entregar argumentos decisivos, incertidumbres, veredicto y experimento verificable. Una ronda inicial, una réplica opcional y un veredicto bastan normalmente.
