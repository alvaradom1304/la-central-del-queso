# upselling — criterios de ingeniería

No optimizar ticket medio si crecen merma, devoluciones o abandono. En alimentos evaluar consumo/almacenamiento y unidad de venta; un formato mayor no aporta valor si se desperdicia. No contabilizar ingreso incremental como contribución: descontar costos variables y descuentos. Si no hay necesidad documentada, mantener como hipótesis de oferta, no recomendar universalmente. Separar bundles complementarios de upgrade y evitar doble conteo con cross-selling. Aceptación debe ser explícita y conservar una vía de compra sencilla.

## Caso adverso determinante

Se propone duplicar gramos para subir ticket aunque el cliente necesita una porción pequeña y el producto vence antes de consumirla.

## Evidencia de aceptación

- Resolver el fallo específico con evidencia y límites
- No cerrar con contradicción material o resultado inventado
- Entregar criterios verificables y responsables operativos según alcance

Registrar entorno, build/versión, entrada, resultado esperado/observado y artefacto. Marcar NOT_RUN cuando no se ejecute; no sustituir una comprobación por una promesa de optimización futura.
