# Workflows declarativos

No están automatizados por este registro. Cada etapa recibe outputs verificados de la anterior y puede saltar etapas ya validadas. El orquestador conserva estado, decisión, evidencia y responsable.

| Workflow | Ruta | Manejo de fallo |
|---|---|---|
| New Venture | opportunity → customer/problem → market → unit economics/caja → model → MVP → GTM → launch → growth | gate HOLD/REVISE; prueba mínima antes de inversión |
| Business Transformation | diagnóstico → causas → target state → prioridades → implementación → medición | no prescribir sobre causa no demostrada |
| Brand/Digital | research → strategy → brand → UX → UI/motion → build/security → QA → launch autorizado | no sacrificar tareas/performance por inmersión |
| Revenue Learning | demand → leads → discovery/qualification → ventas → entrega/retención → aprendizaje marketing | conciliar eventos y ventas, respetar opt-out |
| Operational Scale | registro → conciliación → capacidad → SOP → automatización → prueba de volumen | detener expansión si falla calidad/caja |
| Quality Loop | plan → execute → test → evaluate → diagnose → correct → retest → validate → report | máximo inicial 3 ciclos; detener sin progreso |

Identificar autorizaciones y responsable humano por proyecto. Registrar workflows implementados separadamente con versión/runtime y pruebas; no confundir diseño con estado activo.
