# Calidad de primera entrega de una capacidad

La autorización para completar vacíos permite crear y mejorar capacidades necesarias. No permite declarar terminada una biblioteca por cantidad ni entregar plantillas genéricas como procedimientos expertos. Reservar mejora continua posterior para ajustes menores o cambios de evidencia, no para requisitos omitidos.

Antes de cerrar una skill exigir:

1. Una responsabilidad repetible y salida diferente de las capacidades ya existentes; resolver por frontmatter/alias, no por presencia de un nombre de carpeta.
2. Procedimiento específico con decisiones, precondiciones, alternativas, límites, estados adversos y recuperación pertinente. No basta cambiar el título de un protocolo común.
3. Contrato de datos útil para otro ejecutante: campos, unidades/periodos, fuentes, desconocidos, estado y criterio de aceptación; tipar datos cuando se usen en automatización.
4. Al menos un caso adverso propio del dominio y un caso independiente con entradas no vistas; conservar salida cruda y evaluación contra criterios predefinidos. Un caso diseñado no es ejecutado.
5. Fuentes pertinentes; distinguir documentación consultada, fuente sugerida y requisito de verificar vigencia al ejecutar. No adjuntar la misma lista de URLs a dominios no relacionados.
6. Pruebas realmente ejecutadas de cualquier script incluido y análisis de límites. YAML/JSON válido solo acredita estructura.
7. Personalización sustantiva a Agency OS: decisión objetivo→evidencia→implementación→prueba→KPI, operación y tradeoffs comerciales. No copiar identidad/claims/activos de un tercero para llamarlo exclusivo.
8. Versiones coherentes, referencias resolubles, conservación del original y guardado confirmado. Un envío fallido no es instalación.

Separar dos ejes: calidad del paquete (incompleto/revisable/apto para uso delimitado) y evidencia de desempeño (estructural/comportamiento contextual/cliente/producción). EXPERIMENTAL no excusa un procedimiento incompleto; describe límites de evidencia de desempeño. UNKNOWN baseline es legítimo cuando no hay datos de cliente y no impide un método técnicamente completo; impide prometer mejora medida.

No aprobar con promedio un error crítico, una responsabilidad sin dueño, fabricación de evidencia o pérdida/duplicación de una tarea esencial. La fábrica puede crear esqueletos como trabajo intermedio, pero debe revisar y completar procedimiento, contrato y escenarios antes de entregar. El generador inicial no certifica profundidad ni crea conocimiento experto por conteo.

Evaluar KEEP/REVISE/REVERT con evidencia de uso, impacto y regresiones. Registrar cambios de contexto separados de cambios del método. No rehacer discovery aprobado sin nueva evidencia.
