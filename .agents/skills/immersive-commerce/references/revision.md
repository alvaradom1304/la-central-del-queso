# Revisión y medición

Adaptar controles al alcance. No marcar un control como realizado por figurar en esta lista.

| Etapa | Evidencia para revisar |
|---|---|
| Estrategia y recorrido | Objetivo, segmento, oferta, restricciones y tareas clave; supuestos visibles. |
| UX y diseño | Comprensión del precio y entrega; acceso directo a compra; uso móvil, foco, contraste y movimiento reducido. |
| Implementación | Selección/cantidades, estados, validación, persistencia si aplica y errores; comprobar desde UI hasta datos. |
| Inmersión y WPO | Pruebas en dispositivos/red representativos, recursos cargados, estabilidad visual y fallback sin 3D. |
| Pedido y operación | Pedido recibido/confirmado con ID cuando aplica; duplicados, stock, cancelación, entrega y pago correctamente modelados. |
| SEO y medición | Contenido rastreable, configuración comprobada y eventos sin duplicados ni datos sensibles. |
| Optimización | Baseline, periodo/muestra, margen y conversión por etapa; límites de atribución y siguiente experimento. |

Registrar versión, entorno, evidencia observada, pendientes, responsable y decisión: avanzar, avanzar con condiciones o revisar. No confundir una demo con integración productiva, un clic con venta o una prueba sintética con comportamiento real de clientes.

Para experimentar, formular hipótesis, cambio, KPI, protección de margen/UX, periodo o muestra justificados y criterio de detener/revertir. No concluir causalidad de una comparación temporal sin considerar campañas, estacionalidad y cambios simultáneos.
